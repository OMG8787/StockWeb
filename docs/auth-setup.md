# 帳號系統部署步驟（Google 試算表＋Apps Script）

架構與權限說明見 README「帳號與權限」。這份只寫第一次部署要做的事，約 10 分鐘。

## 1. 建立試算表與 Apps Script

1. 到 Google 雲端硬碟新增一份空白 **Google 試算表**，例如命名「股情雷達帳號」。**不需要分享給任何人。**
2. 試算表上方選單「**擴充功能 → Apps Script**」。
3. 刪掉編輯器裡預設的程式碼，把本 repo 的 `gas/Code.gs` 整份貼上，按儲存。
4. 上方函式下拉選單選 **`setup`**，按「執行」。第一次會要求授權：審查權限 → 選帳號 → 進階 → 前往（不安全）→ 允許。
5. 執行完在下方「執行記錄」會看到一行 `API_SECRET（…）：xxxxxxxx`，**複製起來**（之後也可以在「專案設定 → 指令碼屬性」看到）。
6. 回到試算表，會看到 `Users`、`Sessions`、`LoginLog` 三個工作表。

## 2. 部署成網頁應用程式

1. 右上角「**部署 → 新增部署作業**」，類型選「**網頁應用程式**」。
2. 「執行身分」選 **我**，「誰可以存取」選 **所有人**。
   - 「所有人」只代表網址可以被呼叫；沒有 API_SECRET 的請求一律被拒絕，而且這個金鑰只放在 Vercel 伺服器，瀏覽器拿不到。
3. 按「部署」，複製「**網頁應用程式網址**」（結尾是 `/exec`）。

之後如果修改了 `gas/Code.gs`：「部署 → 管理部署作業 → 編輯（鉛筆）→ 版本：新版本 → 部署」，網址不會變。

## 3. 設定環境變數（Vercel 與本機 .env.local）

| 變數 | 內容 |
|---|---|
| `AUTH_GAS_URL` | 第 2 步的 `/exec` 網址 |
| `AUTH_GAS_SECRET` | 第 1 步的 API_SECRET |
| `AUTH_SECRET` | 任意 32 字以上隨機字串（登入 cookie 簽章用；更換會讓所有人重新登入） |
| `ADMIN_SETUP_CODE` | 任意字串，建立第一個管理員時要輸入；建好後可刪除 |
| `SERVICE_API_KEY` | 24 字以上隨機字串，本機腳本讀正式站 API 用（本機 .env.local 放同一組） |

隨機字串可用：`node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`

不再使用、可以從 Vercel 刪除的舊變數：`SITE_PASSWORD`、`AUTH_GOOGLE_ID`、`AUTH_GOOGLE_SECRET`。

## 4. 建立第一個管理員

1. 部署後打開網站，會自動跳到登入頁。試算表裡還沒有任何帳號時，登入頁會變成「**建立第一個管理員帳號**」。
2. 填帳號、名稱、密碼，以及 `ADMIN_SETUP_CODE` 的設定碼，按「建立並登入」。這個帳號擁有全部權限（含 13 最高管理員）。
3. 之後到右上角選單「👥 帳號與權限」新增其他帳號、勾選權限。

## 本機開發

沒設定 `AUTH_GAS_URL` 時，本機自動改用 `.cache/auth-dev-store.json` 當假資料庫（行為與試算表版相同），
打開 http://localhost:3000 會直接出現「建立第一個管理員」（本機不需要設定碼，除非你設了 `ADMIN_SETUP_CODE`）。
想從頭來過就刪掉這個檔案。正式環境（`NODE_ENV=production`）沒設定試算表會直接報錯，不會改用本機檔案。
